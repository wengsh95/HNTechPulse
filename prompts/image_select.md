## 硬排除规则（违反即失败，绝对不可选择）

以下类型的图片即使它是唯一候选也必须在 reason 中标注为 "fallback: <原因>"：

1. **错误/拦截页面**：WAF 防火墙拦截页、403/404/500 错误页、"Access Denied"、"Request Blocked"、CDN 报错、空白浏览器页。画面特征：大标题"Sorry"/"Error"/"Blocked"、纯文字报错、盾牌/感叹号图标。
2. **人物肖像/头像**：单一真实人脸的头部特写或半身照、作者头像、员工证件照、社交媒体头像。注意：文件名含 `BLURPLE`、`avatar`、`portrait`、`headshot`、`profile` 通常是头像；正方形（宽=高）真人照片极大概率是头像。
3. **纯 logo/图标/徽章**：只含一个 logo 而无其他实质内容的图片（但品牌标识图如"Claude"文字+装饰图案属于合格的主题图，不算纯 logo）。
4. **竖图**：高度 > 宽度的图片。

## 选择优先级（从高到低，严格按此顺序评估）

1. **主题直接相关** ★ 最重要：图片画面直接展示故事核心主题——产品实物、品牌视觉标识（如 Anthropic 故事出现 Claude 品牌图、Apple 故事出现 Apple 产品图）、技术架构示意图、事件现场照片。**判断标准：一个不了解故事的人看到图片能否大致猜到话题？能则优先。**
2. **高质量新闻配图**：来自原文页面的新闻编辑插图、信息图表、产品截图，且画面内容与故事标题/关键词语义一致。
3. **有意义的页面截图**：原文报道页面、产品发布页、GitHub 仓库首页、官方公告——前提是截图内容可读且与故事主题一致。
4. **Bing 搜索概念图**：仅当以上都不可用，且画面与故事主题语义相关时才考虑。必须核实画面内容（不是只看 query 或文件名）。
5. **Fallback**：所有候选都不理想时，选最不差的，并在 reason 中说明。

## 其他规则

- `selected_path` 必须逐字复制候选图片中的某一个 `path`，不要改写、补全、猜测或输出 URL。
- 页面原图通常比 Bing 搜索结果更可信。
- 对新闻报道，优先选择原文媒体页面、官方来源或真实新闻照片。不要用论坛/Reddit/社交媒体评论截图替代新闻来源截图，除非故事本身就是关于该评论串。
- 避免明显 AI 生成、夸张合成或广告感很强的概念图；只有当页面图不可用且没有更可信的真实图时才选择。
- Bing 图片可以替换页面截图，但必须满足至少一项：画面明显更切题、`same_domain_as_story=true`、或当前 auto_selected 是错误页/头像/不可用图。
- 第三方 Bing 图即使文件名或 query 命中主题词，也要检查画面是否真的对应故事。
